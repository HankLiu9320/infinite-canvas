# 待测试

## Go 后端 Codex App Server 渠道

- 管理后台新增 `Codex App Server` 协议，默认提供 `codex-text`、`codex-image`，可选择实际执行模型。渠道无需接口地址和 API Key，使用运行 Go 后端的用户的 Codex 登录状态。
- 设置 `CODEX_ENABLED=true` 后，首次拉取模型或生成时由 Go 启动 app-server，完成握手并复用进程；异常退出后下次调用重新启动，后端退出时关闭子进程。后端启动时将该渠道未完成的图片任务标记为失败，用户可重新生成。
- 文本请求适配 Chat Completions 和 Responses 普通/流式响应，支持参考图片理解。工作流草稿入口也走 Go app-server，工具调用输出转换为现有前端工具格式；需验证工具请求与后续结果回传。
- 图片生成和编辑通过原生 `image_generation` 工具执行，仅接收协议里的真实图片产物；接入既有后台图片任务、轮询和停止功能。账号无生图能力、额度不足、超时或断开时应显示错误。
- 每个请求创建独立临时工作目录，读取图片后清理。一个 app-server 串行执行生成任务，排队时间计入渠道超时。停止任务应中断 turn，不回写迟到结果。
- 验证登录账号的系统渠道权限、模型开放范围、预扣算力点、失败退款、调用日志，以及 `images`、`chat`、`responses` 三种图片请求模式。个人直连渠道不能使用后端 Codex 身份。
- Docker 运行镜像新增固定版本 Codex CLI，登录目录和任务目录放在已有 `data` 挂载下；仍需用户构建镜像并验证设备登录和实际调用。

已用本机 Codex CLI 0.161.0 检查协议定义，并完成初始化、登录状态读取、模型列表（7 个模型）、临时线程创建与取消订阅的连通性验证。未执行项目构建、语法检查或真实文本/图片生成，画布端到端行为仍需用户测试。

- 修正配置保存提示：没有视频等对应模型渠道时，不再要求填写该类默认模型；本地直连误选 `codex-text` / `codex-image` 时提示使用管理员配置的云端渠道；云端没有可用渠道时提示先配置后台。需验证只有 Codex 文本/图片渠道的保存与提交。

- 系统渠道未配置时，AI 请求直接返回「没有可用模型渠道」，避免通用 API 错误掩盖配置原因。开启普通用户云端权限不会自动创建 Codex 渠道，还需配置渠道和 `CODEX_ENABLED`。

- Codex 生图失败详情：处理独立错误事件，保留错误类型和附加说明；上游重试耗尽或额度不足及时失败，额度限制显示恢复时间。超时显示渠道限制、已等待时间及排队/连接/生成阶段，上游重试中的超时附带最近一次错误。未产出图片时显示 Codex 回复；画布错误区支持多行滚动，并补充任务错误详情兜底。需验证额度不足、上游重试、排队超时、无产物以及长错误信息展示。
